Module 3 Week 1: 802.1Q Frame Tagging and Transit Links

The Transit Link Architecture

A standard Layer 2 switchport configured as an access link can only carry traffic for a single assigned Virtual Local Area Network. When connecting multiple switches together, deploying a dedicated physical cable for every isolated database is unscalable and consumes excessive hardware resources. The IEEE 802.1Q standard resolves this limitation by allowing a single physical transit link to carry traffic for multiple broadcast domains simultaneously. Cisco networking terminology defines this transit connection as a trunk link.

The 802.1Q Frame Tagging Process

To maintain logical isolation across a shared physical wire, the transmitting switch must mathematically identify the source broadcast domain of every frame before placing it on the transit link.

The hardware achieves this by inserting a 4 byte tag directly into the standard Ethernet header immediately following the Source MAC Address field. This tag contains the exact numeric identifier of the originating segment. This insertion increases the maximum Ethernet frame size from 1518 bytes to 1522 bytes.

When the receiving switch processes the incoming data, it reads this numerical tag, strips the 4 byte field from the header to restore the original standard Ethernet frame, and forwards the data strictly to the ports assigned to that specific numeric identifier in its local Content Addressable Memory table.

The Native Segment and Untagged Traffic

By default, an 802.1Q transit link expects all incoming traffic to possess a mathematical tag. However, switches generate internal control traffic that lacks this tag. To process this untagged traffic, the IEEE standard utilizes a native database.

Any frame arriving on a transit link without an 802.1Q tag is automatically placed into this native database. By default, Cisco hardware assigns VLAN 1 as the native segment. For security compliance, administrators must manually change this native assignment from the default database to a dedicated and unused numeric identifier to prevent unauthorized access across the infrastructure.

Cisco IOS Transit Link Configuration

To establish a transit link between infrastructure components, administrators must enter interface configuration mode and execute the following specific commands.

  • switchport mode trunk : Hardcodes the physical interface to operate strictly as a transit link.
  • switchport trunk native vlan [ID] : Reassigns the database identifier used to process untagged frames arriving on the interface.
  • switchport trunk allowed vlan [List] : Restricts the transit link to only carry traffic for explicitly defined logical segments, blocking all unapproved databases from crossing the wire.
  • show interfaces trunk : Displays all active transit links on the device, including their current operational status and the specific segments permitted to traverse the connection.
