Chapter Introduction

Chapter 5, Cloud Connectivity, focuses on how organizations reach their cloud resources. Building a virtual network in the cloud is only half the job; users, offices, and data centers still need a reliable and secure path to it. This chapter compares the main options: VPN connections that run encrypted tunnels across the public internet, and dedicated private circuits that bypass the internet entirely.

You will also see how cloud networks connect to each other through peering and hub-and-spoke designs, and how bandwidth, latency, cost, and redundancy shape the choice of connection. These decisions determine whether a hybrid cloud performs well, stays secure, and keeps running when a link fails.

Why This Matters: Most organizations run a hybrid environment, with some systems on-premises and some in the cloud. The connection between them carries everything from student records to backups, so choosing the wrong type can mean slow applications, exposed data, or an outage when a single link goes down.

Learning Objectives

  • Compare internet-based and private cloud connections
  • Explain site-to-site and point-to-site VPNs
  • Describe dedicated circuits such as ExpressRoute and Direct Connect
  • Connect virtual networks with peering and hub-and-spoke designs
  • Evaluate bandwidth, latency, cost, and redundancy needs
  • Secure hybrid traffic with encryption and firewalls
  • Troubleshoot common connectivity problems

Comparing Connection Options

Option How it connects Best for AWS equivalent
Site-to-site VPN Encrypted IPsec tunnel between an on-premises VPN device and the cloud VPN gateway, across the internet Offices and data centers that need an always-on, low-cost link Site-to-Site VPN
Point-to-site VPN VPN client on a single device connects to the cloud VPN gateway Remote workers and administrators Client VPN
Dedicated circuit (ExpressRoute) Private connection through a connectivity provider that never crosses the public internet High bandwidth, predictable latency, and sensitive workloads Direct Connect
VNet peering Links two cloud virtual networks over the provider's backbone Hub-and-spoke designs and separating workloads VPC peering, Transit Gateway

Design tip: Many organizations pair a dedicated circuit with a site-to-site VPN as a backup, so traffic fails over to the internet path if the private circuit goes down.
