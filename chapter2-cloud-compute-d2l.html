Chapter Introduction

Chapter 2, Cloud Compute, looks at the processing power behind every cloud service. It starts with virtualization, the technology that lets a hypervisor divide one physical server into many virtual machines, each with its own operating system. You will see how the same idea works in an on-premises data center running Hyper-V or VMware and in the cloud, where you choose a VM size and the provider takes care of the hardware and hypervisor.

The chapter then moves to lighter-weight options. Containers package an application with only the libraries it needs and share the host's operating system, so they start in seconds and run the same way everywhere. Serverless computing goes further: you upload a function, and the provider runs it only when an event triggers it, charging only for the time it runs.

Why This Matters: Compute is usually the biggest part of a cloud bill and the first decision in any cloud project. Picking a VM when a container or a function would do, or leaving a VM running when no one needs it, wastes money every hour. Knowing the options lets you match each workload to the right tool.

Learning Objectives

Two Types of Hypervisor

Type 1 (bare metal): runs directly on the hardware. Hyper-V, VMware ESXi, and the hypervisors cloud providers use are Type 1.
Type 2 (hosted): runs as an app on a desktop OS. VirtualBox and VMware Workstation are Type 2, common for labs and testing.

On-Premises Virtualization vs. Cloud VMs

Area On-premises In the cloud
Hardware You buy, rack, power, cool, and replace the servers The provider owns and maintains the physical servers
Hypervisor You install, patch, and license it (Hyper-V, VMware ESXi) The provider runs it; you never see or manage it
Sizing Limited by the capacity of the hosts you own Pick a VM size and resize it when needs change
Cost Large up-front purchase (capital expense) Pay as you go while VMs run (operating expense)
Scaling Order more hardware, which can take weeks Add VMs in minutes, or let autoscaling do it
Availability You design clusters and failover yourself Built-in options such as availability zones
You manage Everything from the hardware up The guest OS, apps, and data

Cost tip: In Azure, shutting a VM down from inside Windows or Linux leaves it allocated, and you keep paying for compute. Stop it from the portal so its status reads "Stopped (deallocated)" to stop compute charges.
